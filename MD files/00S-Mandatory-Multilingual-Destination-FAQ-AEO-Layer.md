# 00S — Mandatory Multilingual Destination FAQ / AEO Layer
## Jordan Story Tours — EN / DE / FR / IT

**Priority:** CRITICAL
**Extends:** `00R-Multilingual-Destination-Content-SEO-AEO-GEO.md`
**Applies to:** every indexable destination page

# 1. Objective

Every published destination page MUST contain a destination-specific FAQ / traveler-questions section.

The purpose is to make each destination page more useful to travelers and strengthen:
- AEO / direct-answer coverage
- long-tail SEO coverage
- GEO/entity relationships
- internal linking
- topical completeness
- conversion into relevant Jordan Story Tours

Do not create FAQs merely to manipulate rankings. Questions must reflect genuine traveler needs.

# 2. Mandatory Rule

No indexable destination page is complete without a researched FAQ block unless there is a documented editorial reason that questions would provide no user value.

Do NOT reuse the same generic FAQ set across all destinations.

Each destination requires its own questions.

# 3. Recommended Quantity

Use quality rather than a fixed quota.

General guidance:
- Tier 1 destinations: 8–12 strong questions
- Tier 2 destinations: 6–10
- Tier 3 destinations: 5–8

Petra, Wadi Rum, Dead Sea and Amman may justify additional questions when research reveals genuinely different intents.

Do not pad a page to hit a number.

# 4. Question Research

For EACH language research questions independently:

EN — English traveler queries
DE — German traveler queries
FR — French traveler queries
IT — Italian traveler queries

Do not create English questions and mechanically translate them.

Record research in:
- `docs/DESTINATION-AEO-MAP-EN.md`
- `docs/DESTINATION-AEO-MAP-DE.md`
- `docs/DESTINATION-AEO-MAP-FR.md`
- `docs/DESTINATION-AEO-MAP-IT.md`

For every question store:
`destination | locale | question | intent | answer source | volatility | target page | related link | status`

# 5. FAQ Intent Categories

Research a balanced mix where relevant:

## Understanding
- What is the destination famous for?
- Why is it important?
- What makes it different?

## Time
- How much time do visitors need?
- Is one day enough?

## Route / Combination
- Can it be combined with another destination?
- How does it fit a Jordan itinerary?

## Access
- How is it reached from Amman/Petra/Aqaba where relevant?

## Experience
- What are the main things to see/do?

## Accommodation
- Is an overnight stay useful?
- Where do travelers normally base themselves?

## Season / Timing
- When is a suitable time to visit?
Only answer with appropriate nuance and current evidence.

## Family / Accessibility / Traveler Type
Use only when reliable information is available.

## Jordan Story Tours
- Which verified tours visit this destination?
- Can it be included in a private/custom Jordan itinerary?

Do not turn every FAQ into an advertisement.

# 6. Answer Format

Preferred visible format:

`Question → direct answer (first 1–2 sentences) → concise useful explanation → contextual internal link when helpful`

The first sentence should genuinely answer the question.

Avoid introductions such as:
“That's a great question!”

Avoid keyword stuffing.

# 17. Time-Sensitive Answers

Mark questions involving:
- entrance fees
- opening hours
- trail seasons
- transport schedules
- visa rules
- weather-dependent access
as `VOLATILE`.

Use maintained verified data with:
`source | verified_at | status`

Do not invent current numbers.

# 18. Destination FAQ vs Tour FAQ

Keep intent separated.

DESTINATION:
“How much time do you need in Petra?”

TOUR:
“Are Petra entrance fees included in this tour?”

DESTINATION:
“Can Petra and Wadi Rum be combined?”

TOUR:
“Does Classic Tour 1 visit Wadi Rum?”

Commercial answers MUST come from verified tour master data.

# 19. Internal Linking from Answers

Where useful:
- destination answer → relevant guide
- destination answer → verified tour collection
- destination answer → related destination
- destination answer → custom tour page

Do not add a CTA to every answer.

# 20. GEO / Entity Reinforcement

FAQs should naturally clarify real relationships.

Examples:
`Petra → Jordan → Wadi Musa → Nabataean heritage`
`Madaba → Mount Nebo → Dead Sea route`
`Jerash → ancient Gerasa → northern Jordan`
`Aqaba → Red Sea → Wadi Rum`

Do not stuff entity names unnaturally.

# 21. Multilingual Quality

German questions must sound like real German traveler questions.
French questions must sound native in French.
Italian questions must sound native in Italian.

Localize answers editorially; preserve factual meaning.

# 22. Visible Content

FAQ questions and answers must be visible to users in normal HTML/text.

Accordion UI is acceptable if:
- accessible
- keyboard usable
- content remains available in rendered/indexable HTML
- important answers are not fetched only after a user interaction

# 23. Structured Data Warning

Do NOT treat FAQ schema as the reason for creating these sections.

The visible FAQ content itself is valuable.

Do not use `QAPage` markup for destination FAQs written by Jordan Story Tours; QAPage is intended for pages where users can submit answers to a single question.

If FAQ-related structured data is used, it must match visible content and current search-engine eligibility/policies. Do not promise FAQ rich results.

# 24. Avoid FAQ Spam

Forbidden:
- 30 near-identical questions
- city-name swapping
- keyword permutations
- repeated answers
- answers written only to repeat keywords
- fake first-hand claims
- unsupported superlatives
- copied competitor FAQs

Every question should help a traveler make a decision, understand the place, or plan the trip.

# 25. Placement

Recommended page position:

`Main destination content → Tours Visiting Destination → Planning/FAQ block → Related destinations/guides → CTA`

For very large pages, selected FAQs may appear contextually within relevant sections with a consolidated FAQ near the end.

# 26. FAQ UI

Use a clean accessible accordion or question cards.

Requirements:
- clear question text
- readable direct answer
- no excessive animation
- mobile friendly
- accessible expanded/collapsed state
- deep linking to FAQ anchors where practical

# 27. FAQ Anchors

Where useful create stable anchors such as:
`#how-many-days-in-petra`
`#petra-from-amman`

Do not create separate thin URLs for every FAQ unless a question genuinely deserves a substantial standalone guide.
